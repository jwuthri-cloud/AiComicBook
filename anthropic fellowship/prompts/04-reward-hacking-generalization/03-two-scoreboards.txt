EXACT PRINTED PANEL CONTENT:
1. SCOREBOARD ONE: THE GAME
Hack rate = exploited episodes divided by eligible episodes. Also record intended task success, reward, training compute, and whether the model had a real opportunity to exploit. A low hack count may reflect low ability.
2. SCOREBOARD TWO: TRANSFER
Use new, sealed tasks that were never used to choose recipes. Score misleading reports, inappropriate shortcuts, and other predefined behavior. Include honest mistakes and harmless failures so evaluators do not label every error misalignment.
3. READ THE RECIPE EFFECT
Estimate each ingredient’s average effect and important interactions. Maybe diversity matters only without character training. Show uncertainty across independent runs. Episodes from one run are related; thousands of episodes do not replace multiple seeds.
4. CHECK THE ALTERNATIVES
Could the effect come from lower skill, different training strength, chat formatting, or an evaluator’s taste? Match capability where possible, use blinded manual checks, and test fresh task families and a second model lineage.
5. HOW TO READ A NULL
No wider misalignment in this setup can still teach us which boundary conditions matter. It does not prove global safety. Reduced transfer with equal hacking is more informative than reduced transfer simply because the model cannot hack.
6. WORD KEY + CHECK
RL = reinforcement learning. Factorial experiment = testing combinations of ingredients. Held-out means reserved for evaluation. Check: which observation supports broader transfer, and which only shows the original glitch?
