1. COUNT THE BEHAVIOR
Hack rate = exploited episodes divided by eligible episodes. Score intended task success separately. Use sandbox action logs and independent checks so the reasoning monitor does not define its own ground truth.
2. COUNT THE VISIBLE CLUES
Among verified hacking episodes, measure monitor recall at a fixed false-positive rate on honest episodes. Also manually label explicit shortcut discussion. Report both: no explicit words does not guarantee that all detectable evidence disappeared.
3. THE DANGEROUS PATTERN
If hacking stays similar while monitor recall falls, visibility may have degraded. If both hacking and alarms fall, behavior may have improved. Compare uncertainty across seeds before treating either pattern as a real effect.
4. RULE OUT EASY EXPLANATIONS
Match or stratify by task difficulty, success, response length, and hack type. Check whether shorter text merely reduces the evidence available. Compare fixed monitoring budgets and manual labels; audit whether the monitor misunderstood a new writing style.
5. TEST TRANSFER
Evaluate held-out tasks, new seeds, and selected larger models. Freeze monitor prompts and thresholds before each final test. A refreshed monitor is a useful secondary repair experiment, but cannot replace reporting failure of the original frozen monitor.
6. WORD KEY + CHECK
RL = reinforcement learning. CoT = chain of thought. Recall = verified positive cases detected divided by all verified positive cases. False positive = flagging an honest case. A quiet trace does not establish deliberate intent to hide.
